# Astraudit · 12‑Monats‑Roadmap 2026‑05 → 2027‑05

> **Zweck.** Ein praktischer Fahrplan für ein ganzes Jahr — eine
> Datei, in die du immer wieder zurückkehren kannst. Jeder Monat hat
> ein klares Thema, 3–6 konkrete Items, eine ehrliche Aufwands‑
> schätzung **kalibriert auf Agent‑Velocity** (nicht Mensch‑Wochen),
> und einen festen Qualitäts‑Gate‑Block am Monatsende. Nichts darf
> grün bleiben, wenn Tests, Typecheck, Bundle‑Budget, Lighthouse
> oder a11y rot werden — jede Phase prüft beides.
>
> **Kalibrierung.** Eine *Agent‑Session* ≈ ein fokussierter PR
> (lesen, ändern, Tests anpassen, push, PR aufmachen, CI grün).
> In dieser Umgebung schafft das ein Lauf in ~30–90 Min. „Sessions“
> in Klammern sind die ehrliche Untergrenze; rechne mit Faktor 1.5
> wenn ein Item Reviews oder Recherche triggert.
>
> **Anti‑Roadmap bleibt Gesetz.** Kein Backend, kein Login, keine
> AI‑Inferenz, öffentliche Repos only. Jeder neue Punkt unten muss
> die vier Constraints respektieren — oder er fliegt raus, bevor er
> startet.
>
> **Sequenzierung.** Phasen 1–7 in `ROADMAP.md` sind die Grundlage
> (Phase 7 / Track 0 ist abgeschlossen, Tracks A–D ge­seq­uenced
> auf Monate 2–4 unten). Ab Monat 7 wird Phase 8 (Tiefe pro
> Ökosystem) und Phase 9 (Ecosystem‑Integrationen) konkret.

---

## Monatliches Pflichtprogramm (jeder Monat)

Bevor irgendein Feature‑Item gestartet wird, läuft *jeden Monat*
einmal dieser Block (1 Session, ~30 Min). Wenn er rot ist, hat er
Priorität vor allem anderen.

- **Health‑Sweep.** `npm test` · `npm run typecheck` · `npm run
  build` · `npm run check:bundle-size` · `npm run check:audit`.
  Jede Drift dokumentiert + committed.
- **Dependency‑Triage.** `npm outdated` lesen, alle Patch/Minor
  bumpen, Major‑Bumps als separate PRs öffnen (Dependabot‑Reviews
  abarbeiten).
- **Snapshot‑Resync.** Playwright‑Visuals durchlaufen lassen,
  flaky Snapshots nicht stumpf `--update-snapshots`en, sondern
  Ursache klären (Font‑Loading, Animation‑Race, etc.).
- **Honesty‑Check.** `scripts/honesty-check.ts` über die
  Sample‑Repos — kein neuer „Lüge“‑Eintrag akzeptiert.
- **Quality‑Gate‑Proof.** Lighthouse / a11y / CodeQL Workflows
  grün auf `main`.

## Monat 1 · 2026‑05 → 2026‑06 · Foundation Hardening

**Thema.** Nach dem v1.0.0‑Launch + Dep‑Bump das CI‑Fundament so
robust machen, dass die nächsten 11 Monate kein Tag mit
„nichts geht mehr nach `npm install`" beginnt.

- **M1.1 Bundle‑Budget‑Per‑Chunk‑Bericht.** `check:bundle-size`
  erweitern: nicht nur Pass/Fail, sondern Diff zur letzten
  `main`‑Größe als Markdown‑Tabelle. Bot postet als PR‑Kommentar.
  (2 Sessions)
- **M1.2 Dependabot‑Gruppierung.** `.github/dependabot.yml`
  grouping: alle `@types/*` ein PR, alle `eslint*` ein PR,
  Major‑Bumps separat. Verhindert die Flut aus dem letzten
  Bump‑Zyklus. (1 Session)
- **M1.3 Renovate‑Bot evaluieren.** Side‑by‑side mit Dependabot
  testen. Wenn Renovate die Snapshot‑Reset‑Loops besser
  automatisiert → migrieren. (2 Sessions)
- **M1.4 CI‑Caching‑Audit.** Playwright‑Browser, `node_modules`,
  Vite‑Cache. Ziel: Wall‑Clock der `quality.yml` < 4 Min.
  (1–2 Sessions)
- **M1.5 Pre‑commit‑Hook.** `husky` + `lint-staged`: typecheck
  + tests on changed files. Erspart 80 % der CI‑Roundtrips.
  (1 Session)

**Quality‑Gate‑Proof (M1).** Alle 5 Workflows < 6 Min E2E,
Bundle‑Diff‑Kommentar live, 0 ungetestete Major‑Bumps in flight.

## Eskalations‑Protokoll (für jeden Monat)

Wenn ein Item nicht in den geschätzten Sessions fertig wird:

1. **Erste Session über Limit:** Item bleibt, Scope wird
   geschnitten (kleinster sinnvoller Lieferumfang als MVP).
2. **Doppelte Session über Limit:** Item wird in 2 Items
   gesplittet, eins ins nächste Monatsthema verschoben.
3. **Dreifache Session über Limit:** Item‑Stopp + Retro‑Notiz
   in dieser Datei (Sektion „Lessons Learned" am Ende anhängen).
   Niemand bricht ein Q ein, um *ein* Item zu retten.
