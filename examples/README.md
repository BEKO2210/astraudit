# Astraudit examples

Real, generated samples that show what each export format looks
like end-to-end. Every file in here was produced by running
Astraudit's own engine against a representative fixture and saving
the result with no hand-editing.

## What's here

```
examples/
├── README.md                     # this file
└── sample-audit/                 # one fictional repo audited via runAudit()
    ├── audit.md                  # Markdown export — pasteable into a GitHub issue
    ├── audit.json                # JSON export — feed it to jq / dashboards
    └── audit.adoc                # AsciiDoc — Antora / Asciidoctor pipelines
```

## Reproducing the samples

The sample set is regenerated by [`scripts/sample-exports.ts`](../scripts/sample-exports.ts):

```bash
npx tsx scripts/sample-exports.ts
```

That writes the files into `.audit-cache/` (gitignored). The copy
under `examples/sample-audit/` is the version we ship in the repo
so reviewers can preview the formats without running anything.

## Using the JSON in a CI gate

The JSON export carries a stable `schema` + `schemaVersion` field
so downstream tooling can pin against it. A minimum-grade gate in
GitHub Actions:

```yaml
- name: Audit project + assert score floor
  run: |
    npx tsx scripts/audit-self.ts > audit.txt
    grep -E '^[A-Z]' audit.txt | head -3
    # Replace with your own threshold check, e.g.:
    score=$(jq '.score.total' examples/sample-audit/audit.json)
    [ "$score" -ge 80 ] || { echo "Score $score below floor"; exit 1; }
```

The full schema is documented in
[`src/lib/export/auditExport.ts`](../src/lib/export/auditExport.ts);
key invariants are locked by the contract test at
[`tests/lib/export/auditExport.test.ts`](../tests/lib/export/auditExport.test.ts).

## How the Markdown reads in a real PR

The Markdown export uses standard GitHub-Flavored Markdown — bold,
tables, fenced code blocks, ordered lists, severity emojis. Drop
the contents into an issue or PR description and it renders
identically to how you see it in any editor.

## How the AsciiDoc reads in Antora / Asciidoctor

`audit.adoc` uses `=` / `==` headings, `|===` table delimiters,
and `[source,sh]` code blocks. Antora and Asciidoctor.js both
parse it out of the box. If you publish docs via that pipeline,
drop the file under `modules/ROOT/pages/` and add it to the nav.
